## Что такое SmartRoute?

SmartRoute — это веб-приложение для дистрибьюторов, которое автоматически строит оптимальные маршруты доставки для нескольких машин. Диспетчер загружает список магазинов (вручную или через Excel), указывает машины, нажимает кнопку — и получает готовые маршруты на карте с ссылками на Яндекс Навигатор.

## Где что находится

### Фронтенд (то, что видит пользователь в браузере)

**Папка:** `artifacts/smartroute/src/`

Написан на **React** (JavaScript-библиотека для интерфейсов) + **Vite** (инструмент быстрой сборки).

| Файл | Что делает |
|---|---|
| `App.tsx` | Главный файл — решает, какую страницу показать по URL |
| `pages/home.tsx` | Стартовая страница с кнопками навигации |
| `pages/stores.tsx` | Список магазинов, форма добавления, загрузка из Excel |
| `pages/route.tsx` | Выбор магазинов и машин, запуск оптимизации |
| `pages/result.tsx` | Карта Leaflet с маршрутами, кнопки Яндекс / WhatsApp |
| `pages/analytics.tsx` | Графики пробега и экономии (Recharts) |
| `components/layout.tsx` | Боковое меню и шапка, которые видны на всех страницах |
| `components/ui/` | Кнопки, таблицы, карточки — стандартные элементы интерфейса |

### Бэкенд (серверная часть, невидимая пользователю)

**Файл:** `artifacts/api-server/main.py`

Написан на **Python** + **FastAPI**. Это единственный файл, в котором сосредоточена вся серверная логика.

| Что находится в main.py | Описание |
|---|---|
| `init_db()` | Создаёт таблицы в базе данных при первом запуске |
| `seed_demo_data()` | Заполняет базу тестовыми магазинами Москвы |
| `geocode_address()` | Переводит текстовый адрес в координаты (широта/долгота) |
| `solve_vrp()` | **Мозг системы** — алгоритм оптимизации маршрутов |
| `haversine_meters()` | Считает расстояние между двумя точками на карте |
| `calculate_savings()` | Рассчитывает экономию в км и рублях |
| `yandex_nav_url()` | Формирует ссылку на Яндекс Навигатор |
| `whatsapp_url()` | Формирует ссылку для отправки маршрута в WhatsApp |
| `import_stores()` | Читает Excel-файл и загружает магазины в базу |
| `download_stores_template()` | Отдаёт пустой шаблон Excel для заполнения |
| `/api/analytics/*` | Запросы к базе данных для статистики |

## Где OR-Tools (алгоритм оптимизации)

**Файл:** `artifacts/api-server/main.py`, функция `solve_vrp()` (строки 107–154)

**OR-Tools** — это библиотека от Google для решения задачи "Travelling Salesman Problem" (коммивояжёр) и её расширения — VRP (Vehicle Routing Problem, задача маршрутизации транспортных средств).

Что делает `solve_vrp()`:
1. Получает список координат: сначала склад/депо, потом все магазины
2. Строит матрицу расстояний (от каждой точки до каждой другой) через `haversine_meters()`
3. Запускает алгоритм OR-Tools с ограничением: максимум 10 секунд на расчёт
4. Возвращает список маршрутов — какой водитель едет куда и в каком порядке
5. Если OR-Tools недоступен (не установлен) — переходит к простому запасному алгоритму (делит магазины поровну между машинами)

---

## Где GraphHopper

**GraphHopper в проекте не используется.**

Расстояния считаются по формуле Гаверсина (Haversine) — это математический расчёт расстояния между двумя точками на сфере (Земле) по их координатам. Это "расстояние по прямой", без учёта реальных дорог.

Функция: `haversine_meters()` в `main.py` (строки 98–104).

## Где геокодирование (адрес → координаты)

**Файл:** `artifacts/api-server/main.py`, функция `geocode_address()` (строки 157–178)

Используется **Nominatim** — бесплатный сервис геокодирования от OpenStreetMap.

Как работает:
1. Получает текстовый адрес: `"Москва, ул. Ленина, 5"`
2. Делает запрос к Nominatim API
3. Получает координаты: `(55.7558, 37.6173)`
4. Кэширует результат в памяти (не запрашивает повторно)
5. При импорте из Excel — делает паузу 1.1 секунды между запросами (ограничение Nominatim: не более 1 запроса в секунду)

## Где Excel-парсер

**Файл:** `artifacts/api-server/main.py`

Используется библиотека **openpyxl**.

| Функция/эндпоинт | Что делает |
|---|---|
| `download_stores_template()` → `GET /api/stores/template` | Создаёт и отдаёт пустой .xlsx шаблон с заголовками |
| `import_stores()` → `POST /api/stores/import` | Читает загруженный .xlsx, извлекает строки, геокодирует адреса, сохраняет в базу |

Формат Excel-файла:
| Название | Адрес | Время с | Время до | Время разгрузки мин |
|---|---|---|---|---|
| Магазин Пятёрочка | ул. Ленина 5 | 09:00 | 18:00 | 15 |

## Где модели базы данных

**Файл:** `artifacts/api-server/main.py`, функция `init_db()` (строки 56–95)

База данных — **PostgreSQL** (управляется Replit). Три таблицы:

### Таблица `stores` — магазины
| Поле | Тип | Что хранит |
|---|---|---|
| id | число | Уникальный номер магазина |
| name | текст | Название магазина |
| address | текст | Адрес |
| lat, lon | дробные числа | Координаты (широта, долгота) |
| geocode_status | текст | Статус геокодирования: `found` / `not_found` / `pending` |
| time_window_from | текст | Начало временного окна (напр. `09:00`) |
| time_window_to | текст | Конец временного окна (напр. `18:00`) |
| unload_minutes | число | Время разгрузки в минутах |
| created_at | дата/время | Дата добавления |

### Таблица `route_sessions` — история маршрутов
| Поле | Тип | Что хранит |
|---|---|---|
| id | число | Уникальный номер сессии |
| date | текст | Дата построения маршрута |
| num_vehicles | число | Количество машин |
| total_km | дробное | Суммарный пробег по маршруту |
| saved_km | дробное | Сколько км сэкономлено |
| saved_rub | число | Экономия в рублях |
| num_points | число | Количество точек доставки |
| created_at | дата/время | Дата создания |

### Таблица `route_session_stores` — связь маршрут–магазин
| Поле | Тип | Что хранит |
|---|---|---|
| session_id | число | К какому маршруту относится запись |
| store_id | число | К какому магазину |
| visit_order | число | Порядковый номер посещения |

## Где аналитика

**Бэкенд:** `artifacts/api-server/main.py`, эндпоинты `/api/analytics/*`
**Фронтенд:** `artifacts/smartroute/src/pages/analytics.tsx`

Четыре вида статистики:
- **Итоговая** — общий пробег, экономия км, экономия рублей за всё время
- **По дням** — пробег и экономия за последние 30 дней (линейный график)
- **По месяцам** — пробег и экономия за последние 12 месяцев (столбчатая диаграмма)
- **Топ-10 магазинов** — какие магазины посещались чаще всего

Графики строятся библиотекой **Recharts**.

## Где оптимизация маршрутов

Цепочка обработки при нажатии кнопки "Построить маршрут":

1. **Фронтенд** (`pages/route.tsx`) — пользователь выбирает магазины и машины, отправляет запрос
2. **Бэкенд** (`/api/route/build` в `main.py`) — получает запрос, загружает координаты магазинов из базы
3. **`solve_vrp()`** — OR-Tools строит оптимальные маршруты
4. **`calculate_savings()`** — считает экономию
5. **Ответ** содержит маршруты, ссылки на Яндекс и WhatsApp
6. **Фронтенд** (`pages/result.tsx`) — показывает карту Leaflet с маршрутами

## API — как фронтенд общается с бэкендом

Все запросы идут через префикс `/api`. Описание контракта хранится в `lib/api-spec/openapi.yaml`. На его основе автоматически генерируются TypeScript-хуки в `lib/api-client-react/` — фронтенд использует их вместо прямых HTTP-запросов.

Полный список API-методов — в файле **API.md**.
