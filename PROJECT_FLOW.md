# SmartRoute — Как работает система

> Пошаговое объяснение того, как данные движутся через систему — от загрузки Excel до отображения маршрута на карте.

---

## Общая картина

```
Пользователь
    │
    ▼
Браузер (React-приложение)
    │  отправляет HTTP-запросы
    ▼
Python-сервер (FastAPI, порт 8080)
    │         │                    │
    ▼         ▼                    ▼
 OR-Tools  Nominatim          PostgreSQL
(алгоритм) (геокодер)         (база данных)
```

---

## Поток 1: Загрузка магазинов из Excel

```
Диспетчер скачивает шаблон
        │
        │  GET /api/stores/template
        ▼
Сервер создаёт Excel-файл через openpyxl
        │
        │  файл .xlsx
        ▼
Диспетчер заполняет шаблон: название, адрес, время работы
        │
        │  POST /api/stores/import (загружает файл)
        ▼
Сервер читает Excel через openpyxl
        │  берёт каждую строку
        ▼
Для каждого адреса → Nominatim (OpenStreetMap)
        │  "Москва, ул. Ленина, 5"
        │  → пауза 1.1 сек (ограничение API) →
        │  ← (55.7558, 37.6173)
        ▼
Сохраняет магазин в PostgreSQL (таблица stores)
        │  geocode_status = "found" или "not_found"
        ▼
Возвращает итог: сколько загружено / ошибок
        │
        ▼
Фронтенд показывает баннер: "8 из 10 магазинов импортированы"
```

**Файлы кода:**
- Фронтенд: `artifacts/smartroute/src/pages/stores.tsx` — форма загрузки
- Бэкенд: `artifacts/api-server/main.py` → функция `import_stores()`, `geocode_address()`

## Поток 3: Оптимизация маршрутов (главный сценарий)

```
Диспетчер открывает страницу "Маршрут"
        │
        │  GET /api/stores → загружает список всех магазинов
        ▼
Диспетчер выбирает галочками нужные магазины
Диспетчер указывает машины (названия, грузоподъёмность)
        │
        │  POST /api/route/build
        │  {
        │    store_ids: [1, 3, 5, 7],
        │    vehicles: [{name: "Газель 1", capacity_kg: 1500}],
        │    use_time_windows: true
        │  }
        ▼
Сервер загружает координаты выбранных магазинов из PostgreSQL
        │
        ▼
Строит матрицу расстояний через haversine_meters()
        │  считает расстояние от каждой точки до каждой другой
        │  (прямое расстояние по воздуху, без учёта дорог)
        ▼
solve_vrp() запускает Google OR-Tools
        │  алгоритм: PATH_CHEAPEST_ARC (жадный старт) + GUIDED_LOCAL_SEARCH (улучшение)
        │  ограничение: 10 секунд на расчёт
        │  учитывает грузоподъёмность машин (если указана)
        ▼
Сервер собирает результат:
        │  - для каждой машины: список магазинов в порядке объезда
        │  - расстояние маршрута
        │  - примерное время в пути
        │  - ссылка на Яндекс Навигатор
        │  - ссылка для WhatsApp
        ▼
calculate_savings() считает экономию:
        │  неоптимизированный маршрут = оптимизированный × 1.3
        │  экономия км = разница
        │  экономия рублей = сэкономленные км × 12 руб/км
        ▼
Сохраняет сессию в PostgreSQL (таблицы route_sessions, route_session_stores)
        │
        │  возвращает JSON с маршрутами
        ▼
Фронтенд сохраняет результат в localStorage браузера
        │
        ▼
Перенаправляет на страницу результата (/result)
        │
        ▼
result.tsx читает данные из localStorage
        │
        ▼
Показывает карту Leaflet:
        │  - цветные линии маршрутов (каждая машина — свой цвет)
        │  - маркеры для каждого магазина
        │  - всплывающие подсказки с адресом
        ▼
Справа — список маршрутов с кнопками:
        │  "Яндекс Навигатор" → открывает навигатор с маршрутом
        │  "WhatsApp" → открывает мессенджер с готовым сообщением водителю
```

**Файлы кода:**
- Фронтенд (выбор): `artifacts/smartroute/src/pages/route.tsx`
- Бэкенд (расчёт): `artifacts/api-server/main.py` → `build_route()`, `solve_vrp()`
- Фронтенд (карта): `artifacts/smartroute/src/pages/result.tsx`

## Поток 4: Просмотр аналитики

```
Диспетчер открывает страницу "Аналитика"
        │
        │  GET /api/analytics/summary   ─┐
        │  GET /api/analytics/daily     ─┤  параллельно
        │  GET /api/analytics/monthly   ─┤
        │  GET /api/analytics/top-stores─┘
        ▼
Сервер делает SQL-запросы к таблице route_sessions
        │
        ▼
Фронтенд строит графики через Recharts:
        │  - линейный: пробег по дням (последние 30 дней)
        │  - столбчатый: экономия по месяцам
        │  - таблица: топ-10 магазинов
        ▼
Показывает 4 карточки с KPI:
        │  - Построено маршрутов: X
        │  - Общий пробег: X км
        │  - Сэкономлено: X км
        │  - Экономия бюджета: X ₽
```

**Файлы кода:**
- Фронтенд: `artifacts/smartroute/src/pages/analytics.tsx`
- Бэкенд: `artifacts/api-server/main.py` → `get_analytics_summary()`, `get_analytics_daily()` и др.

## Как устроена связь фронтенд ↔ бэкенд

```
OpenAPI-спецификация (lib/api-spec/openapi.yaml)
        │  описывает все API-методы (что принимает, что возвращает)
        │
        ▼ (команда: pnpm --filter @workspace/api-spec run codegen)
        │
        ▼
Автогенерация кода (Orval)
        │
        ├── lib/api-client-react/  ← TypeScript-хуки для React
        │       useListStores()      ← загрузить магазины
        │       useCreateStore()     ← добавить магазин
        │       useBuildRoute()      ← построить маршрут
        │       ...
        │
        └── lib/api-zod/           ← схемы валидации данных
```

Фронтенд не пишет HTTP-запросы вручную. Он использует готовые хуки из `api-client-react`, которые были автоматически сгенерированы из спецификации.

## Запуск при старте сервера

При каждом запуске `python main.py`:

```
Сервер стартует
        │
        ▼
init_db() — создаёт таблицы, если их нет
        │
        ▼
seed_demo_data() — проверяет: есть ли магазины в базе?
        │  если нет → добавляет 8 тестовых магазинов Москвы
        │  если есть → ничего не делает
        ▼
Сервер готов принимать запросы на порту 8080
```

---

## Резервный режим (если OR-Tools не установлен)

Если библиотека OR-Tools недоступна (например, не установлена), система не ломается. Она переходит в **жадный режим**:

```
Все магазины делятся поровну между машинами
(без оптимизации порядка объезда)
```

Маршруты будут построены, но неоптимально. В логах появится предупреждение:
`"OR-Tools not available, using greedy fallback"`

## Схема взаимодействия компонентов

```
┌──────────────────────────────────────────────┐
│               БРАУЗЕР                         │
│                                              │
│  pages/stores.tsx  → управление магазинами   │
│  pages/route.tsx   → настройка оптимизации  │
│  pages/result.tsx  → карта + маршруты        │
│  pages/analytics   → графики аналитики       │
│                                              │
│  Все запросы через api-client-react hooks    │
└────────────────────┬─────────────────────────┘
                     │ HTTP/JSON
                     ▼
┌──────────────────────────────────────────────┐
│           PYTHON-СЕРВЕР (FastAPI)             │
│                                              │
│  geocode_address() → Nominatim (интернет)    │
│  solve_vrp()       → OR-Tools (локально)     │
│  import_stores()   → openpyxl (локально)     │
│  аналитика         → SQL-запросы             │
└────────────────────┬─────────────────────────┘
                     │ SQL
                     ▼
┌──────────────────────────────────────────────┐
│           POSTGRESQL (Replit)                 │
│                                              │
│  stores              (магазины)              │
│  route_sessions      (история маршрутов)     │
│  route_session_stores (маршрут ↔ магазин)   │
└──────────────────────────────────────────────┘
```
