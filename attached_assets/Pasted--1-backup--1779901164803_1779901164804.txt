ВАЖНЫЕ ПРАВИЛА РАБОТЫ ПЕРЕД НАЧАЛОМ:
 1. Бэкап: Перед любыми изменениями обязательно сделай backup проекта:
 ◦ `git add .`
 ◦ `git commit -m "backup before refactor"`
 ◦ `git push origin main`
Убедись, что push выполнен успешно.
 2. Проверка: После КАЖДОГО завершённого шага:
 ◦ Запускать backend и frontend.
 ◦ Проверять, что проект собирается без ошибок.
 ◦ Исправлять ошибки сразу.
 ◦ Делать commit и push в GitHub.
 3. Пошаговость: НЕ выполнять весь рефакторинг одним большим изменением. Работать строго пошагово: завершил шаг -> протестировал -> сохранил в GitHub -> только потом следующий шаг.
 4. Фокус: НЕ переписывать несвязанные части проекта. НЕ делать глобальный рефакторинг без необходимости.
 5. Документация: После каждого шага обновлять: `CONTEXT.md`, `ARCHITECTURE.md`, `ROADMAP.md`, `CHANGELOG.md`.
 ◦ ОБЯЗАТЕЛЬНО веди `SESSION_NOTES.md`, где пиши: что сделано, какие файлы изменены, что осталось, риски, что проверить вручную.
 6. Ошибки: Если появляются ошибки — НЕ переходить дальше, сначала полностью восстановить рабочее состояние.
 7. Отчетность: После каждого шага показывай: измененные файлы, запущенные команды, результаты тестов.
 8. GitHub: GitHub — главный источник истины. Все изменения должны быть там.

ТЕХНИЧЕСКОЕ ЗАДАНИЕ (SMARTROUTE REFACTOR)
ЦЕЛЬ: Провести рефакторинг проекта SmartRoute для перехода на Production Ready уровень.

Шаг 1: Синхронизация API и Кодогенерация
 1. Изучи `artifacts/api-server/main.py` и найди эндпоинты `/api/stores/import` и `/api/stores/template`.
 2. Обнови `lib/api-spec/openapi.yaml`, добавив эти пути в спецификацию.
 3. Запусти `pnpm --filter @workspace/api-spec run codegen` для обновления хуков.
 4. Перепиши логику импорта в `stores.tsx`, заменив `raw fetch` на сгенерированные хуки.

Шаг 2: Серверное хранение результатов

 3. Убери использование `localStorage` для передачи данных между `/route` и `/result`. После `buildRoute.mutate` делай редирект на `/result/{id}`.

Шаг 3: Улучшение VRP-логики и параметров
 1. В `main.py` добавь глобальную переменную `TRAFFIC_MULTIPLIER = 1.2` (коэффициент пробок) и используй её в расчетах времени.
 2. Обнови модель `VehicleInput`, добавив поле `average_speed` (индивидуальная скорость для каждого авто).
 3. Интегрируй эти параметры в основной цикл расчета VRP.

Шаг 4: UI/UX и Мобильная адаптация
 1. Создай общий UI-компонент `StatusBadge` в `src/components/ui`, устранив дублирование кода `Badge` на страницах.

 3. Добавь кнопку “Копировать ссылку на маршрут” для быстрой передачи водителю.
