ЗАДАЧА: Спроектировать и внедрить полноценный интерфейс ручного создания заявок на день (Daily Orders Builder) для SmartRoute.

ПЕРЕД НАЧАЛОМ РАБОТЫ:

Полностью изучи текущую архитектуру проекта.
Изучи все страницы:
Stores
Orders
Route Builder
Result
Import History
Изучи существующие модели БД:
stores
daily_orders
route_sessions
order_import_history
Изучи все API, связанные с заявками и импортом.
Подготовь краткий архитектурный отчёт:
какие сущности уже существуют;
какие можно переиспользовать;
какие изменения потребуются.

НЕ ПИШИ КОД ДО ЗАВЕРШЕНИЯ АУДИТА.

⸻

ЦЕЛЬ

Упростить создание заявок настолько, чтобы диспетчер мог работать БЕЗ Excel.

Пользователь должен иметь возможность создать полный маршрутный день вручную прямо в SmartRoute.

⸻

ТРЕБОВАНИЯ UX/UI

Это должно выглядеть как полноценный рабочий инструмент диспетчера.

Приоритеты:

Минимум кликов.
Максимум наглядности.
Работа без обучения.
Интерфейс должен быть понятен человеку, который плохо владеет компьютером.

Сначала предложи UX-макет и пользовательский сценарий.

⸻

ФУНКЦИОНАЛ

Создать новый раздел:

“Создать заявки на день”

или

“Ручные заявки”

⸻

ОСНОВНОЙ СЦЕНАРИЙ

Пользователь выбирает дату.

После этого видит таблицу.

Колонки:

Магазин
Вес (кг)
Объём (м³)
Сумма (руб)
Комментарий

Магазин выбирается из существующей базы магазинов.

Поиск должен работать мгновенно.

Поиск по:

названию
адресу
телефону
клиенту

⸻

МАССОВОЕ ДОБАВЛЕНИЕ

Очень важно.

Нужна кнопка:

“Добавить магазин”

После выбора магазина появляется новая строка.

Нужно быстро добавить десятки магазинов подряд.

⸻

АВТОСОХРАНЕНИЕ

Все изменения должны сохраняться автоматически.

Если пользователь закрыл страницу случайно — данные не теряются.

⸻

КОНТРОЛЬ ОШИБОК

Перед сохранением:

нельзя добавить один магазин дважды;
нельзя сохранить отрицательный вес;
нельзя сохранить отрицательный объём;
показывать понятные сообщения.

⸻

ИНТЕГРАЦИЯ С МАРШРУТАМИ

После создания заявок должна быть кнопка:

“Построить маршрут”

Нажатие должно переводить пользователя на Route Builder.

Все созданные заявки автоматически выбираются.

⸻

ДОПОЛНИТЕЛЬНЫЙ UX

В верхней части страницы показывать:

количество магазинов;
общий вес;
общий объём;
общую сумму.

В режиме реального времени.

⸻

ПРОИЗВОДИТЕЛЬНОСТЬ

Не создавать лишних запросов.

Использовать существующие таблицы и API максимально эффективно.

Не дублировать данные.

Не создавать тяжёлые решения.

⸻

РЕЗУЛЬТАТ РАБОТЫ

Сначала предоставить:

Архитектурный анализ.
UX/UI концепцию.
Список изменений backend.
Список изменений frontend.
Оценку рисков.

Только после согласования приступить к внедрению.

После внедрения предоставить:

список изменённых файлов;
описание изменений;
список тестов;
результаты тестов.
