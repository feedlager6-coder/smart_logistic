SMARTROUTE — СИСТЕМА ПОЛЬЗОВАТЕЛЕЙ И ИЗОЛЯЦИЯ ДАННЫХ

Перед началом внимательно изучи весь проект SmartRoute, текущую архитектуру авторизации, JWT, структуру БД, stores, depots, routes, import_jobs, текущую логику импорта и маршрутизации.

ВАЖНО:

Не вносить изменения вслепую.

Сначала провести аудит существующей реализации авторизации и хранения данных.

После аудита подготовить план изменений.

Главная цель:

Сделать возможность безопасно выдавать тестовые аккаунты потенциальным клиентам.

КРИТИЧЕСКОЕ ТРЕБОВАНИЕ

Все данные пользователей должны быть полностью изолированы друг от друга.

Пользователь не должен видеть:

* магазины другого пользователя;
* склады другого пользователя;
* маршруты другого пользователя;
* результаты импорта другого пользователя;
* любые служебные данные других пользователей.

Проверить существующую архитектуру.

Если изоляция уже реализована частично — использовать её.

Если нет — реализовать корректно.

ТРЕБУЕМАЯ ФУНКЦИОНАЛЬНОСТЬ

1. Админ-панель пользователей

Создать раздел:

Настройки → Пользователи

Доступ только админу.

Функции:

* список пользователей;
* дата создания;
* последний вход;
* статус аккаунта;
* активен/отключён.

2. Создание пользователя

Админ может:

* указать логин;
* указать пароль;
* создать аккаунт.

После создания пользователь может войти в систему.

3. Отключение пользователя

Кнопка:

Отключить

После отключения:

* вход запрещён;
* данные сохраняются.

4. Удаление пользователя

Кнопка:

Удалить пользователя

Перед удалением показать подтверждение.

Если возможно — реализовать мягкое удаление.

5. Сброс пароля

Админ может:

* задать новый пароль пользователю.

6. Проверка безопасности

Провести аудит:

* JWT;
* middleware;
* owner_id;
* SQL-запросов.

Проверить:

нет ли мест, где пользователь может получить данные другого пользователя.

Провести поиск по проекту.

Проверить все:

* SELECT;
* UPDATE;
* DELETE;
* INSERT.

7. UX

Интерфейс должен быть максимально простым.

Не добавлять:

* роли;
* приглашения по email;
* мультиорганизации;
* сложную систему прав.

Нужна только простая выдача тестовых аккаунтов.

ТЕСТЫ

После реализации обязательно:

1. Создать тестового пользователя.
2. Войти под ним.
3. Создать магазины.
4. Проверить, что админ видит свои данные.
5. Проверить, что тестовый пользователь видит только свои данные.
6. Проверить маршруты.
7. Проверить склады.
8. Проверить импорт Excel.
9. Проверить удаление пользователя.
10. Проверить отключение пользователя.

ОТЧЁТ

После завершения предоставить:

* список изменённых файлов;
* список новых таблиц/полей БД;
* список исправленных уязвимостей;
* результаты тестирования;
* список оставшихся рисков;
* рекомендации по следующему этапу развития системы.

Перед завершением убедиться, что проект собирается без ошибок и вся функциональность протестирована.
