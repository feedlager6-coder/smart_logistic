SMARTROUTE — FINAL RELEASE CANDIDATE AUDIT

КОНТЕКСТ

SmartRoute готовится к первой демонстрации потенциальному клиенту.

Потенциальный клиент: Максим.
Максим влияет на решение о покупке системы.

Основная цель:

НЕ добавлять функционал ради функционала.

Задача — довести существующий продукт до максимально надёжного состояния перед демонстрацией.

Перед началом:

1. Изучи весь проект.
2. Изучи текущую архитектуру.
3. Изучи changelog.
4. Изучи документацию.
5. Изучи последние изменения.
6. Изучи существующие бизнес-процессы SmartRoute.

После изучения проведи полный аудит системы.

⸻

ЭТАП 1. FULL PRODUCT AUDIT

Проверь систему полностью как:

* новый пользователь;
* диспетчер;
* логист;
* руководитель компании;
* администратор.

Проверь каждый пользовательский сценарий.

Проверить:

1. Авторизация

* вход
* выход
* повторный вход
* неверный пароль
* блокировка после rate limit

2. Админка

* создание пользователя
* смена пароля
* блокировка
* разблокировка
* выдача admin
* снятие admin
* удаление пользователя

Проверить все защитные механизмы.

Особенно:

* нельзя удалить себя
* нельзя заблокировать себя
* нельзя снять admin у себя
* нельзя удалить последнего администратора
* нельзя деактивировать последнего администратора

3. Импорт

* Excel
* дубликаты
* отсутствие города
* город по умолчанию

Проверить UX.

4. Магазины

* создание
* редактирование
* удаление
* геокодирование
* фильтр “без координат”
* экспорт

5. Маршрутизация

* 1 автомобиль
* несколько автомобилей
* история маршрутов
* повторное открытие маршрута

6. Навигация

* Яндекс Навигатор
* WhatsApp
* маршрутные листы

7. Аналитика

* история
* показатели
* расчёты экономии

⸻

ЭТАП 2. PRODUCTION READINESS

Проверь всё глазами клиента.

Найди:

* сломанные кнопки
* битые ссылки
* неработающие действия
* ошибки консоли браузера
* ошибки Network
* лишние запросы
* UX-проблемы
* технический долг

Проверить:

* нет ли ошибок React
* нет ли ошибок API
* нет ли ошибок PostgreSQL
* нет ли ошибок авторизации

⸻

ЭТАП 3. SECURITY AUDIT

Повторно проверить:

* изоляцию пользователей
* owner_id
* доступ к чужим магазинам
* доступ к чужим маршрутам
* доступ к admin API

Провести реальные тесты запросами.

⸻

ЭТАП 4. DEMO READINESS

Проверить:

Если завтра придёт Максим:

Будет ли продукт выглядеть профессионально?

Ответить:

Что вызывает доверие?
Что вызывает вопросы?
Что может отпугнуть клиента?

Исправить всё, что напрямую влияет на демонстрацию.

⸻

ЭТАП 5. ДОКУМЕНТАЦИЯ

Повторно пройти по ВСЕМ файлам документации.

Проверить:

README
ARCHITECTURE
CHANGELOG
ROADMAP
API
COMMERCIAL
ONBOARDING
DEPLOY

и все остальные документы.

Удалить устаревшую информацию.

Обновить всё, что не соответствует текущему состоянию проекта.

⸻

ЭТАП 6. GITHUB

После завершения:

1. Провести финальное тестирование.
2. Убедиться, что приложение запускается.
3. Проверить отсутствие критических ошибок.
4. Выполнить git status.
5. Выполнить commit с понятным сообщением.
6. Выполнить push в GitHub.

Токен GitHub уже настроен через Secrets.

Если push не проходит:

* самостоятельно диагностировать причину;
* исправить;
* повторить push.

⸻

ФИНАЛЬНЫЙ ОТЧЁТ

Предоставить:

1. Что проверено.

3. Что осталось.

Не добавлять новые функции без веской причины.

Главный критерий:

Надёжность.
Стабильность.
Готовность к продаже.
Готовность к демонстрации.
