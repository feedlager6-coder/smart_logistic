Проведи ФИНАЛЬНЫЙ PRODUCTION-АУДИТ проекта SmartRoute как независимый технический директор (CTO), который должен принять решение: можно ли выпускать продукт на первых платных клиентов.

ВАЖНО:

Не добавляй новый функционал ради функционала.
Не занимайся рефакторингом ради красоты кода.
Не переписывай архитектуру без доказанной необходимости.

Твоя задача — найти только реальные проблемы, которые могут:

* привести к потере клиента;
* привести к неверным маршрутам;
* привести к неверным расчётам экономии;
* привести к сбоям в эксплуатации;
* вызвать негативный пользовательский опыт.

═══════════════════════════════════
ШАГ 1. Полное изучение проекта
═══════════════════════════════════

Перед началом аудита:

* изучи весь backend;
* изучи весь frontend;
* изучи OpenAPI;
* изучи документацию;
* изучи все последние изменения;
* изучи существующие тесты.

Сначала получи полную картину проекта.

═══════════════════════════════════
ШАГ 2. Аудит как разные типы пользователей
═══════════════════════════════════

Пройди систему полностью как:

1. Новый пользователь без инструкций.
2. Логист компании.
3. Владелец бизнеса.
4. Курьер/водитель.
5. Технический администратор.

Для каждого сценария:

* опиши путь пользователя;
* укажи возникающие сложности;
* оцени UX;
* найди точки отказа.

═══════════════════════════════════
ШАГ 3. Попытка сломать систему
═══════════════════════════════════

Проведи негативное тестирование.

Проверь:

* пустые файлы;
* битые Excel;
* дубли;
* одинаковые адреса;
* одинаковые координаты;
* 0 магазинов;
* 1 магазин;
* 500+ магазинов;
* 100 машин;
* неверные координаты;
* пустые поля;
* некорректные URL;
* отключённый OSRM;
* отключённый интернет;
* недоступный геокодер;
* повреждённые данные БД.

Цель:
найти ситуации, где продукт ломается, зависает или выдаёт неправильный результат.

═══════════════════════════════════
ШАГ 4. Аудит коммерческой готовности
═══════════════════════════════════

Ответь на вопросы:

1. Можно ли показывать текущие показатели экономии клиентам?
2. Можно ли использовать текущие расчёты в продажах?
3. Какие допущения есть в модели?
4. Есть ли риск обвинений в недостоверных расчётах?
5. Что необходимо явно объяснять клиенту?

═══════════════════════════════════
ШАГ 5. Нагрузочное тестирование
═══════════════════════════════════

Проведи реальные тесты:

* 20 магазинов;
* 50 магазинов;
* 100 магазинов;
* 200 магазинов;
* максимальный реалистичный сценарий.

Для каждого покажи:

* время построения;
* использование памяти;
* количество вызовов внешних API;
* устойчивость.

═══════════════════════════════════
ШАГ 6. Вердикт CTO
═══════════════════════════════════

Раздели все найденные проблемы на категории:

P0 — блокируют продажи.
P1 — желательно исправить до первого клиента.
P2 — можно исправлять после появления клиентов.
P3 — косметика.

Для каждой проблемы:

* доказательство;
* воспроизведение;
* влияние на бизнес;
* приоритет.

═══════════════════════════════════
ШАГ 7. Исправления
═══════════════════════════════════

Исправляй ТОЛЬКО:

* P0;
* P1.

Не трогай P2 и P3.

После каждого исправления обязательно:

* запуск тестов;
* проверка регрессий;
* проверка API;
* проверка frontend.

═══════════════════════════════════
ШАГ 8. Финальный вывод
═══════════════════════════════════

В конце дай однозначный ответ:

ГОТОВ К ПЛАТНОМУ ПИЛОТУ
или
НЕ ГОТОВ К ПЛАТНОМУ ПИЛОТУ

Если не готов — перечисли только оставшиеся блокирующие причины.

Если готов — перечисли оставшиеся риски и вероятность их возникновения.

ШАГ 9. Документация
═══════════════════════════════════

Если были изменения:

обнови полностью:

* CHANGELOG.md
* ARCHITECTURE.md
* CONTEXT.md
* SESSION_NOTES.md
* replit.md

Документация должна на 100% соответствовать текущему состоянию проекта.

Главное правило:

Не искать работу ради работы.
Не добавлять новые функции без доказанной необходимости.
Думать как CTO, который отвечает собственными деньгами за запуск продукта.
