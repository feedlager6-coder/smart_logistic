Ты работаешь с существующей логистической системой маршрутизации.

В репозитории сейчас находится стабильная production-версия проекта.

Поддержки объёма груза (м³) в системе сейчас нет.

Твоя задача — спроектировать и внедрить полноценную поддержку объёма груза по всей системе.

Перед написанием кода сначала полностью изучи проект:

backend;
frontend;
БД;
алгоритм маршрутизации;
импорт заказов;
построение маршрутов;
существующую поддержку веса (кг).

После изучения кратко опиши архитектуру и план изменений.

Только после этого приступай к реализации.

Цель

Сейчас система умеет учитывать только вес.

Нужно добавить второй независимый ресурс:

вес (кг);
объём (м³).

Маршрут должен считаться корректным только если одновременно соблюдаются оба ограничения.

Пример:

машина:

1500 кг
16 м³

заказы:

1200 кг
18 м³

Результат:

маршрут недопустим, несмотря на то что вес проходит.

Backend

Добавить поддержку объёма через весь pipeline.

Необходимо:

VehicleInput

Добавить:

capacity_m3: Optional[float]

Заказы

Добавить volume_m3.

Импорт

Поддержать импорт объёма.

История импорта

Сохранять:

общий вес;
общий объём;
количество заказов;
список нераспознанных магазинов.

VRP

Объём должен участвовать в ограничениях маршрутизации так же, как вес.

Важно:

объём должен быть реальным ограничением оптимизатора, а не только предварительной проверкой.

Проверки

Возвращать ошибку если:

общий объём заказов больше общего объёма машин;
один заказ больше любого кузова.

Frontend

Добавить:

Поле объёма кузова у машины.
Отображение заполнения объёма.
Процент загрузки по объёму.
Отображение объёма в результатах маршрута.
Историю импорта с объёмом.
Отображение нераспознанных магазинов.

Критически важные проверки

При реализации отдельно проверь следующие сценарии.

Ранее при похожей реализации были обнаружены типовые ошибки.

Убедись, что их нет:

Сценарий:

есть ограничение по объёму,
нет ограничения по весу.

Система всё равно должна корректно ограничивать маршруты.

После перераспределения точек между маршрутами ограничения не должны нарушаться.

Если есть этапы:

rebalance;
relocate;
optimize;
post-processing;

после них ограничения должны оставаться валидными.

Любое перемещение заказа между маршрутами должно учитывать:

вес;
объём.

Не должно быть ситуаций:

capacity_m3 работает,
capacity_kg отсутствует,

и система падает из-за NoneType или аналогичных ошибок.

Тестирование

Создай полноценный набор тестов.

Обязательно:

Граничные тесты:

ровно по лимиту;
превышение на 0.0001;
нулевые значения;
отрицательные значения.

Функциональные тесты:

только вес;
только объём;
вес и объём одновременно;
несколько машин;
несколько маршрутов.

Stress Tests:

100 заказов;
1000 заказов;
5000 заказов.

Важно:

не использовать реальные сетевые запросы для стресс-тестов.
