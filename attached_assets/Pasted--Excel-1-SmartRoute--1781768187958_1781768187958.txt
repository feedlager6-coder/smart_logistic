Задача: реализовать поддержку импорта Excel-файлов из 1С в проекте SmartRoute.

Контекст:

Текущий репозиторий — стабильная рабочая версия.

Предыдущая реализация была потеряна и отсутствует в GitHub.

Нужно реализовать функционал заново.

Перед началом:

Изучи текущий механизм импорта магазинов.
Покажи архитектурный план реализации.
Только после этого приступай к изменениям.

Цель:

Сделать так, чтобы пользователь мог загружать типичные Excel-файлы из 1С без ручной переделки таблицы.

Основные требования:

1. Preview перед импортом

После выбора Excel-файла нельзя сразу запускать импорт.

Сначала должен вызываться:

POST /api/stores/import/preview

Preview должен возвращать:

список колонок;
первые строки файла;
предполагаемый mapping.

Пользователь должен увидеть диалог проверки данных.

⸻

2. Column Mapping

В диалоге пользователь должен иметь возможность выбрать:

колонку названия магазина;
колонку адреса;
колонку города;
колонку ссылки Яндекс (если есть);
колонку времени разгрузки (если есть);
колонку временных окон (если есть).

Автоопределение обязательно.

Для поиска названия магазина учитывать:

Контрагент
Клиент
Покупатель
Название
Store Name

Для адреса учитывать:

Адрес
Адрес доставки
Address

⸻

3. Сохранение настроек

После успешного импорта сохранять mapping в localStorage.

При следующем импорте автоматически предлагать последний использованный mapping.

Без БД.

Без новых таблиц.

⸻

4. Критически важная часть — дедупликация строк

Типичная выгрузка 1С содержит:

ООО Ромашка | ул Ленина 1 | Товар А
ООО Ромашка | ул Ленина 1 | Товар Б
ООО Ромашка | ул Ленина 1 | Товар В

Это одна точка доставки.

Перед геокодингом необходимо агрегировать строки.

Ключ дедупликации:

(name + address)

Нормализация:

trim;
lowercase;
схлопывание пробелов.

После агрегации должна остаться одна точка.

Важно:

Дедупликация должна происходить ДО геокодинга.

⸻

5. Обратная совместимость

Старый шаблон SmartRoute должен продолжать работать без изменений.

Если пользователь загрузил старый шаблон:

Название | Адрес | …

импорт должен работать как раньше.

⸻

6. Проверки после реализации

Обязательно выполнить и показать результаты:

Backend:

проверка регистрации всех новых endpoint;
запуск API;
тест preview endpoint;
тест import endpoint.

Frontend:

npm/pnpm typecheck;
build;
отсутствие ошибок TS.

Функциональные тесты:

Тест №1:
Обычный шаблон SmartRoute.

Тест №2:
Файл с колонками:
Контрагент | Адрес доставки

Тест №3:
Файл с дубликатами:

ООО Рыбный мир
ООО Рыбный мир
ООО Рыбный мир

Ожидаемый результат:

3 строки -> 1 уникальная точка.

⸻

7. Финальный отчёт

Перед завершением предоставить:

список изменённых файлов;
список новых функций;
список новых endpoint;
результаты тестов;
список потенциальных рисков.

Не добавлять новые функции вне этой задачи.

Не добавлять интеграции с 1С по API.

Не добавлять многолистовые Excel.

Не добавлять новые таблицы БД.

Реализовать только MVP для удобного импорта Excel-файлов из 1С.
