Ты — старший fullstack-разработчик. Тебе поручено провести полный аудит и исправление интеграции SmartRoute с 1С, которую реализовал предыдущий агент. Интеграция состоит из:
Веб-интерфейс SmartRoute — вкладка «Интеграция с 1С» с двумя вариантами:
«Приложение-агент для Windows» (новый способ).
«Ручная настройка (BSL + API)» (старый способ).
Windows-приложение-агент — десктопное приложение, которое клиент скачивает, устанавливает и подключает к своей 1С.
Бэкенд SmartRoute — API для привязки агентов, генерации кодов, приёма заказов из 1С, отправки статусов.
Предыдущий агент отчитался, что всё реализовано, но на практике агент не подключается: пользователь вводит код привязки, нажимает «Привязать», и ничего не происходит (нет ошибки, нет успеха).
Твоя задача — проверить всю реализацию от начала до конца, найти все баги, несоответствия и недочёты, и исправить их до идеального состояния.
1. Аудит текущей реализации
1.1. Веб-интерфейс (фронтенд)
Найди в репозитории страницу интеграции с 1С (компонент, роут, шаблон).
Проверь:
Есть ли две вкладки: «Приложение-агент» и «Ручная настройка».
Работает ли генератор кодов привязки (кнопка «Сгенерировать код» → код появляется).
Есть ли поле для ввода кода и кнопка «Привязать» в интерфейсе агента (или в мониторинге подключённых баз).
Отправляется ли запрос на бэкенд при нажатии «Привязать» (проверь код, консоль браузера, сетевые запросы).
Найди баги:
Обработчики нажатий (onClick) — есть ли они?
Отправляется ли HTTP-запрос на бэкенд?
Обрабатывается ли ответ (успех/ошибка)?
Выводится ли сообщение пользователю?
1.2. Бэкенд (API)
Найди эндпоинты, связанные с интеграцией 1С:
Генерация кодов привязки (например, POST /api/integrations/1c/codes).
Проверка/активация кода (например, POST /api/integrations/1c/agents/bind).
Скачивание агента (например, GET /api/integrations/1c/agent/download).
Приём заказов от агента (например, POST /api/v1/orders).
Отправка статусов агенту (например, GET /api/v1/deliveries/statuses).
Проверь каждый эндпоинт:
Существует ли он физически (роут, контроллер, обработчик)?
Принимает ли правильные параметры (код привязки, agent_id, токен)?
Возвращает ли корректный ответ (JSON с токеном, статусом)?
Логируется ли что-то при вызове (чтобы отладить)?
Особое внимание — генерация и проверка кодов привязки:
Где хранятся коды (модель, таблица)?
Какие поля (code, user_id, created_at, expires_at, used)?
Как генерируется код (случайная строка SMARTROUTE-XXXX-YYYY)?
Как проверяется (запрос в БД, проверка срока, пометка used)?
Что возвращается при успехе (токен, agent_id)?
Что возвращается при ошибке (неверный код, истёк, уже использован)?
1.3. Windows-агент
Найди папку с агентом (например, apps/1c-agent/).
Проверь структуру:
Есть ли главный файл (например, smartroute_agent_gui.py или main.py)?
Есть ли requirements.txt?
Есть ли скрипты сборки (PyInstaller, Inno Setup)?
Есть ли установщик (SmartRoute_1C_Agent_Setup.exe или .iss скрипт)?
Проверь код агента:
GUI: есть ли поле для ввода кода привязки и кнопка «Привязать»?
Обработчик нажатия: что происходит при нажатии «Привязать»?
Формируется ли HTTP-запрос на бэкенд?
Какой URL (проверь, не опечатка ли)?
Передаётся ли код привязки в правильном формате?
Обрабатывается ли ответ (успех/ошибка)?
Выводится ли сообщение пользователю (в GUI)?
Хранение токена: сохраняется ли токен после успешной привязки (в config.json, зашифрованно)?
Логи: пишет ли агент логи (в файл, в GUI)? Можно ли увидеть, что произошло при нажатии «Привязать»?
Проверь сборку:
Есть ли готовый SmartRoute_1C_Agent_Setup.exe?
Если нет — есть ли инструкция, как его собрать?
Работает ли PyInstaller-конфиг (.spec файл)?
Работает ли Inno Setup-скрипт (.iss)?

3. Исправление проблем
Найди корневую причину, почему привязка не работает, и исправь:
Если проблема во фронтенде:
Нет обработчика нажатия → добавь.
Неправильный URL → исправь.
Нет обработки ответа → добавь (показывай успех/ошибку).
Если проблема в бэкенде:
Эндпоинт не существует → создай.
Эндпоинт возвращает ошибку → исправь логику.
Коды привязки не генерируются → почини генератор.
Коды не проверяются → почини проверку.
Если проблема в агенте:
Нет HTTP-запроса → добавь.
Неправильный формат запроса → исправь.
Нет обработки ответа → добавь.
Ошибка SSL/TLS → добавь обработку (но не отключай проверку полностью).
Если проблема в сборке:
Агент собирается неправильно → исправь PyInstaller-конфиг.
Установщик не работает → исправь Inno Setup-скрипт.
4. Финальные требования
После исправлений:
Клиент скачивает .exe установщик (не .bat, не .zip с Python-скриптами).
Установщик работает на чистой Windows 10/11 (без Python, без 1С).
Агент запускается, показывает GUI.
Клиент вводит код привязки, нажимает «Привязать».
Происходит одно из двух:
Успех: «Привязка успешна», токен сохранён, статус «Подключено».
Ошибка: понятное сообщение («Неверный код», «Сервер недоступен», «Истёк срок кода»).
В логах агента и бэкенда видно, что произошло (для отладки).
