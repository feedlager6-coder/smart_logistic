ЧАСТЬ 2. РЕЖИМЫ ОПТИМИЗАЦИИ

На основании аудита выявлено:

GraphHopper/OSRM возвращают:

(dist_matrix, time_matrix)

Но сейчас:

time_matrix уничтожается в _fetch_matrix()

OR-Tools оптимизирует только расстояние.

Необходимо реализовать поддержку двух режимов.

НО:

НЕ ЗАМЕНЯТЬ текущий режим.

Добавить новый режим через feature flag.

==================================================
BACKEND

Добавить новый параметр API:

optimize_by

Варианты:

“distance”
“time”

По умолчанию:

optimize_by = “distance”

Это критически важно для обратной совместимости.

==================================================
DISTANCE MODE

Текущее поведение.

Ничего не менять.

Маршруты должны строиться идентично текущей версии.

==================================================
TIME MODE

Использовать реальные данные времени.

Не synthetic:

distance / AVG_SPEED

А реальные значения time_matrix.

Необходимо:

1. Не выбрасывать time_matrix в _fetch_matrix()
2. Передавать её в OR-Tools
3. Использовать её как ArcCostEvaluator

ТОЛЬКО если:

optimize_by == “time”

==================================================
