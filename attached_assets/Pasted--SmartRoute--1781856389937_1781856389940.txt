ТВОЯ ЗАДАЧА

Перед началом внимательно изучи весь проект SmartRoute, текущую архитектуру авторизации, систему пользователей, роли, импорт магазинов, маршрутизацию, настройки компании, историю изменений и последние коммиты.

ВАЖНО

Ничего не реализовывай вслепую.

Сначала проведи аудит существующей реализации пользователей и ролей.

После аудита исправь найденные проблемы и только потом внедряй улучшения.

Все изменения должны быть протестированы до и после внесения.

Никаких предположений.

Только проверяемые результаты.

КРИТИЧЕСКАЯ ПРОБЛЕМА:

Единственного администратора можно:

* удалить
* деактивировать
* лишить прав администратора

Это потенциально может полностью лишить систему управления.

⸻

ЭТАП 1
ПОЛНЫЙ АУДИТ СИСТЕМЫ ПОЛЬЗОВАТЕЛЕЙ

Проверь все сценарии:

1. Создание пользователя

Проверить:

* уникальность логина
* обработку пустых полей
* длину пароля
* корректность записи в БД

2. Смена пароля

Проверить:

* старый пароль перестаёт работать
* новый начинает работать
* повторная авторизация проходит успешно

3. Блокировка пользователя

Проверить:

* пользователь не может войти
* существующая сессия завершается
* API недоступно

4. Разблокировка

Проверить:

* вход снова работает

5. Назначение администратора

Проверить:

* появляются административные функции
* права реально работают

6. Снятие прав администратора

Проверить:

* права исчезают
* обычный пользователь не может попасть в админку

7. Удаление пользователя

Проверить:

* удаляются ли магазины
* удаляются ли маршруты
* удаляются ли настройки
* остаются ли “осиротевшие” записи

⸻

ЭТАП 2
УСТРАНЕНИЕ КРИТИЧЕСКИХ ПРОБЛЕМ

Обязательно реализовать:

Нельзя удалить самого себя.

Если текущий пользователь пытается удалить себя:

запретить действие.

Нельзя деактивировать самого себя.

Нельзя снять права администратора самому себе.

Нельзя удалить последнего администратора системы.

Нельзя деактивировать последнего администратора системы.

Нельзя снять права администратора у последнего администратора системы.

Перед удалением пользователя показывать подробную информацию:

* количество магазинов
* количество маршрутов
* дата регистрации

Добавить двойное подтверждение удаления.

Например:

ввести логин пользователя вручную.

⸻

ЭТАП 3
ПРОВЕРКА ИЗОЛЯЦИИ ДАННЫХ

Создать тестовых пользователей:

user_a
user_b

Проверить:

* магазины user_a
* магазины user_b
* маршруты user_a
* маршруты user_b
* настройки user_a
* настройки user_b

Пользователь не должен видеть чужие данные ни через UI, ни через API.

Проверить попытки доступа через прямые URL и запросы.

⸻

ЭТАП 4
УЛУЧШЕНИЕ АДМИНКИ

Добавить в таблицу пользователей:

ЭТАП 5
