# SmartRoute — Интеграции: UX-аудит и дорожная карта

> Документ: архитектура раздела «Интеграции», wizard, журнал синхронизации,
> оценка SmartRoute Connector vs Web, дорожная карта MVP → Enterprise.
> Дата: июнь 2026.

---

## 1. UX-аудит текущего состояния

### 1.1 Критические проблемы

| # | Проблема | Пострадавший | Серьёзность |
|---|---|---|---|
| P1 | Подключение требует Python и редактирования кода | Руководитель, сисадмин | 🔴 Критично |
| P2 | Нет видимости статуса интеграции внутри SmartRoute | Все | 🔴 Критично |
| P3 | API-ключ хранится в текстовом файле без защиты | ИБ / сисадмин | 🔴 Критично |
| P4 | При ошибке — тихий сбой, нет оповещений | Операционная команда | 🟠 Высокое |
| P5 | Обновление ключа требует ручного редактирования файла | Руководитель | 🟠 Высокое |
| P6 | Расписание синхронизации настраивается через cron (ОС) | ИТ/сисадмин | 🟠 Высокое |
| P7 | Нет журнала: когда была синхронизация, сколько загружено | Операционная команда | 🟡 Среднее |
| P8 | Для каждой системы нужно знать разные шаги | Руководитель | 🟡 Среднее |
| P9 | Нет проверки соединения из SmartRoute UI | Сисадмин | 🟡 Среднее |
| P10 | «Ненайденные магазины» требуют ручных действий без подсказок | Оператор | 🟡 Среднее |

### 1.2 Сильные стороны (сохранить)
- Webhook endpoint уже существует (`/api/v1/orders/{token}`) — на него можно нарастить UI
- API-ключи реализованы (scope-based, rotate, revoke)
- Структура данных заявок хорошо определена
- Логика matching магазинов работает

### 1.3 Вывод аудита

Текущий пакет документации и скриптов — это **инструментарий для разработчика**,
а не продукт для бизнес-пользователя. Gap между «скачать скрипт» и
«данные приходят в SmartRoute» слишком велик для нетехнического пользователя.

Целевое состояние: **подключение новой системы — это 5 кликов в UI SmartRoute**,
а не правка конфигурационных файлов.

### 2.5 Диагностика ошибок

Каждое сообщение об ошибке должно содержать:
1. **Что случилось** (понятным языком)
2. **Почему** (техническая причина в деталях)
3. **Что сделать** (конкретные шаги)

```
┌─ Ошибка синхронизации ──────────────────────────────────────────┐
│ ❌  МойСклад не принял наш запрос                               │
│                                                                  │
│ Причина: токен API МойСклад истёк или был отозван              │
│ Код ошибки: HTTP 401 (Unauthorized)                             │
│                                                                  │
│ Что сделать:                                                     │
│ 1. Войдите в МойСклад                                           │
│ 2. Настройки → Безопасность → Токены                            │
│ 3. Создайте новый токен                                          │
│ 4. Вернитесь сюда и нажмите «Обновить учётные данные»           │
│                                                                  │
│ [📋 Скопировать детали ошибки]  [🔑 Обновить учётные данные]    │
└──────────────────────────────────────────────────────────────────┘
```

### 2.6 Механизм обновления (Rotate)

Для каждого подключения — отдельная кнопка **«Обновить учётные данные»**:
1. Открывает форму с одним полем (новый токен/ключ)
2. Автоматически тестирует новые данные
3. Только при успехе — сохраняет и деактивирует старые

## 4. SmartRoute Connector vs Web-интеграция

### 4.1 Сравнение подходов

| Критерий | Web-интеграция (в UI) | Desktop Connector | Webhook (входящий) |
|---|---|---|---|
| Установка | Не нужна | Нужна (MSI/DMG) | Не нужна |
| Опыт пользователя | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| 1С на локальном сервере | ❌ (нет доступа) | ✅ (прямой доступ) | ⚠️ (нужен прокси) |
| МойСклад/Bitrix24 | ✅ (облако → облако) | ✅ | ✅ |
| Google Sheets | ✅ (OAuth) | ✅ | ✅ (через GAS) |
| Обновление | Автоматически | Требует действий | Автоматически |
| Без доступа в интернет | ❌ | ✅ | ❌ |
| Время разработки | 4–6 нед. | 3–4 мес. | 1–2 нед. |

### 4.2 Рекомендация

**Стратегия «Web first + Connector for 1С»:**

**Фаза 1 (Web):** Google Sheets, МойСклад, Bitrix24 — через встроенный UI SmartRoute.
Эти системы облачные — SmartRoute может подключаться к их API напрямую с сервера.
Охватывает ~75% потенциальных клиентов.

**Фаза 2 (Connector):** 1С на локальном сервере — единственная система, где
Cloud→Local напрямую невозможен. Connector = небольшая Windows-служба (~15 МБ),
которая сама опрашивает 1С и проталкивает данные в SmartRoute (push-модель).
Не требует открывать порты в локальной сети.

```
[1С локальный сервер]
        ↓ SmartRoute Connector (Windows Service, задание по расписанию)
        ↓ HTTP POST /api/v1/orders/batch
[SmartRoute Cloud]
```

**Connector не нужно делать сложным:** это py2exe/PyInstaller-бандл из
`sync.py` с GUI-установщиком (Inno Setup). Пользователь запускает `.exe`,
вводит 3 поля, нажимает «Установить как службу» — всё.

## 5. Дорожная карта внедрения

### MVP (4–6 недель) — «Подключиться без кода»

**Цель:** руководитель настраивает первую интеграцию за 15 минут через UI.

**Backend:**
- Таблица `integrations` (id, owner_id, type, name, config_enc, status, schedule, last_sync_at)
- Таблица `integration_sync_logs` (id, integration_id, started_at, status, imported, matched, unmatched, error_json)
- `POST /api/v1/integrations` — создать подключение
- `GET  /api/v1/integrations` — список
- `GET  /api/v1/integrations/{id}` — детали
- `DELETE /api/v1/integrations/{id}` — удалить
- `POST /api/v1/integrations/{id}/test` — проверка соединения (live)
- `POST /api/v1/integrations/{id}/sync` — ручной запуск
- `PUT  /api/v1/integrations/{id}/pause` — пауза / возобновить
- `GET  /api/v1/integrations/{id}/logs` — журнал (пагинация)
- Планировщик: APScheduler в FastAPI — запуск sync по расписанию

**Frontend:**
- Страница `/integrations` — список карточек
- Wizard (5 шагов): выбор системы → credentials → расписание → тест → готово
- Поддерживаемые типы: **Webhook** (любая система) + **МойСклад**
- Страница `/integrations/{id}` — статус, последние 10 записей журнала, кнопки

**Scope MVP:** Webhook + МойСклад (2 системы достаточно для первых клиентов)

**Результат:** первый клиент подключает МойСклад без программиста за 15 мин.

---

### Production (2–3 месяца) — «Все популярные системы»

**Новые типы интеграций:**
- Google Sheets (OAuth 2.0 flow — авторизация в 2 клика)
- Bitrix24 (входящий webhook — пользователь копирует URL в Bitrix24)
- Пользовательский HTTP Webhook (любая система через URL)

**Улучшения UX:**
- Полный журнал с фильтрацией (дата, статус, интеграция)
- Expandable строки журнала с «не найденными» магазинами + кнопка «Добавить»
- Email-оповещения при ошибках (настраивается)
- Диагностический экран: причина ошибки + инструкция
- Статусная страница `/status/integrations` (для мониторинга)

**Безопасность:**
- Шифрование credentials в БД (Fernet / AES-256)
- Токены интеграций отдельно от пользовательских API-ключей
- Audit log для смены credentials

**Developer раздел:**
- Страница `/developers` с webhook URL, Postman, SDK
- Playground: отправить тестовую заявку прямо из UI

---

### Enterprise (6+ месяцев) — «Масштаб и надёжность»

**SmartRoute Connector для 1С:**
- Windows Service (Inno Setup installer, ~15 МБ)
- GUI-конфигуратор (3 поля: URL SmartRoute, API-ключ, строка подключения 1С)
- Авто-обновление через `UPDATE_URL`
- Логи в Event Viewer Windows

**Marketplace интеграций:**
- Каталог готовых шаблонов подключений (поделиться сопоставлением полей)
- Рейтинг и инструкции от сообщества

**Продвинутые возможности:**
- Сопоставление полей с визуальным drag-and-drop
- Трансформации данных без кода (формулы: `{Количество} / 10`)
- Multi-tenant: агент может управлять несколькими организациями
- Conditional sync: «синхронизировать только статус WON»
- Retry logic с экспоненциальным back-off
- Kafka/webhook queue для высоких нагрузок (>1000 заказов/день)

## 6. Архитектура данных (MVP)

```sql
CREATE TABLE integrations (
    id             SERIAL PRIMARY KEY,
    owner_id       INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    type           TEXT NOT NULL,          -- 'moysklad' | 'bitrix24' | 'sheets' | 'webhook' | '1c'
    name           TEXT NOT NULL,          -- название данное пользователем
    config_enc     TEXT,                   -- JSON с credentials, зашифрован Fernet
    status         TEXT DEFAULT 'active',  -- 'active' | 'paused' | 'error'
    schedule_cron  TEXT DEFAULT '30 7 * * *',  -- расписание в cron-формате
    last_sync_at   TIMESTAMP,
    last_error     TEXT,
    created_at     TIMESTAMP DEFAULT NOW()
);

CREATE TABLE integration_sync_logs (
    id             SERIAL PRIMARY KEY,
    integration_id INTEGER NOT NULL REFERENCES integrations(id) ON DELETE CASCADE,
    started_at     TIMESTAMP DEFAULT NOW(),
    completed_at   TIMESTAMP,
    status         TEXT,           -- 'success' | 'warning' | 'error'
    imported       INTEGER DEFAULT 0,
    matched        INTEGER DEFAULT 0,
    unmatched      INTEGER DEFAULT 0,
    error_message  TEXT,
    error_code     TEXT,
    details_json   TEXT            -- JSON: unmatched store names, etc.
);

CREATE INDEX idx_sync_logs_integration ON integration_sync_logs(integration_id, started_at DESC);
```

## 8. Ключевые принципы UX

1. **Zero-code для бизнес-пользователя.** Ни одна настройка не требует редактирования файлов.
2. **Проверка соединения перед сохранением.** Пользователь видит успех/ошибку до завершения wizard.
3. **Понятные ошибки.** Каждое сообщение: что случилось + почему + что делать.
4. **Actionable состояние.** «2 магазина не найдено» → кнопка «Добавить» прямо в логе.
5. **Прогрессивное раскрытие.** Базовая настройка — 3 поля. Продвинутая — за аккордеоном.
6. **Оффлайн-первый для 1С.** Connector работает без постоянного интернета.
