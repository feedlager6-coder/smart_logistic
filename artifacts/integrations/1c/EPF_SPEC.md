# SmartRoute.epf — Спецификация для 1С-разработчика

> Версия: 1.0 | Для: 1С:Предприятие 8.3.15+  
> Этот документ достаточно детален для реализации без дополнительных дизайнерских решений.

---

## ЦЕЛЬ

Клиент SmartRoute должен подключить 1С **за 30 минут без помощи программиста**.  
1С-специалист открывает EPF, вводит URL и ключ, нажимает «Проверить» — готово.

## 5. КОМАНДЫ И ДЕЙСТВИЯ

### 5.1. СмартРоутПроверить

**Триггер:** нажатие кнопки «Проверить соединение»  
**Алгоритм:**

```
1. Валидация:
   - URLSmartRoute не пустой и не содержит "ВАШ-ДОМЕН"
   - APIКлюч не пустой и не содержит "XXXX"
   - Если не прошло → показать ПолеРезультат с ошибкой, остановить

2. HTTP GET /api/healthz
   - Хост: извлечь из URLSmartRoute
   - Порт: 443 (HTTPS) или 80 (HTTP)
   - Таймаут: 10 секунд
   - SSL: ЗащищённоеСоединениеOpenSSL(,,,Ложь)
   - Заголовок Authorization: Bearer {APIКлюч}

3. При ошибке сети:
   → "❌ Нет связи. Проверьте адрес и доступ к интернету. Ошибка: {ОписаниеОшибки}"

4. Код 200:
   → GET /api/v1/stores?page_size=1 (получить кол-во магазинов)
   → "✅ Соединение установлено! Магазинов в базе SmartRoute: N"

5. Код 401:
   → "❌ Неверный API-ключ. Сгенерируйте новый пакет в SmartRoute."

6. Код 403:
   → "❌ Ключ не имеет права orders:write."

7. Прочее:
   → "❌ Сервер ответил кодом {код}."

8. Записать строку в ТаблицаЖурнал (ДатаВремя=Сейчас, Статус, Описание)
```

---

### 5.2. СмартРоутОтправить

**Триггер:** нажатие кнопки «Отправить заявки»  
**Алгоритм:**

```
1. Взять дату из ПолеДатаДоставки
   - Если дата пустая → "Укажите дату доставки!", остановить

2. Показать KPI в ПолеРезультат: "⏳ Получаем заказы из 1С..."

3. Выполнить запрос к базе 1С:
   ВЫБРАТЬ
     З.Контрагент.Наименование     КАК Магазин,
     З.Контрагент.Код              КАК КодКонтрагента,
     З.Контрагент.Телефон          КАК Телефон,
     З.[РеквизитАдреса]            КАК Адрес,
     З.[РеквизитКол]               КАК Количество,
     З.[РеквизитВеса]              КАК Вес,
     З.Комментарий                 КАК Комментарий,
     З.Номер                       КАК НомерДокумента
   ИЗ Документ.[ИмяДокумента] КАК З
   ГДЕ З.[РеквизитДаты] = &ДатаДоставки
     И НЕ З.ПометкаУдаления
     И З.Проведён

   При ошибке запроса:
     → Показать детальную диагностику (какие реквизиты неверны)
     → Записать в ЖурналРегистрации уровень Ошибка
     → Остановить

4. Если результат пустой:
   → "ℹ️ Нет проведённых заказов на {дата}."

5. Собрать массив заявок (JSON-объектов) по каждой строке:
   {
     "store_name":        Магазин,
     "counterparty_code": КодКонтрагента,   ← ОБЯЗАТЕЛЕН
     "address":           Адрес,
     "city":              ГородПоУмолчанию,
     "phone":             Телефон,
     "delivery_date":     "ГГГГ-ММ-ДД",
     "quantity":          Количество (мин. 1),
     "weight_kg":         Вес,
     "products":          Комментарий,
     "order_number":      НомерДокумента,
     "external_id":       НомерДокумента
   }
   Строки без Магазина — пропустить, считать Пропущено++

6. Сформировать тело запроса:
   {
     "orders":             [массив],
     "replace_date":       true,
     "auto_create_stores": true
   }

7. Показать в ПолеРезультат: "⏳ Отправляем {N} заявок..."

8. POST /api/v1/orders/batch с повторами:
   - Максимум 3 попытки
   - Пауза 5 сек между попытками
   - Таймаут: 30 сек

9. Разобрать ответ:
   200/201 → показать статистику (создано, совпало, новых точек)
   401     → неверный ключ
   403     → нет прав
   422     → ошибка данных (показать первые 500 символов ответа)
   429     → слишком много запросов
   прочее  → код + первые 300 символов ответа

10. Записать строку в ТаблицаЖурнал
11. Записать в ЖурналРегистрации ("SmartRoute.Синхронизация", Информация)
```

## 8. РАБОТА С СЕТЬЮ (SSL / HTTPS)

```
ЗащитаSSL = Новый ЗащищённоеСоединениеOpenSSL(
    Неопределено,   // Клиентский сертификат — не нужен
    Неопределено,   // Хранилище ключей — не нужно
    Неопределено,   // Цепочка сертификатов — не нужна
    Ложь            // НЕ проверять цепочку — критично для Windows Server 2012/2016
);
```

**Почему `Ложь`:** Большинство 1С-серверов на Windows Server 2012–2016 не могут верифицировать Let's Encrypt сертификаты (отсутствует корневой сертификат ISRG Root X1). Параметр `Ложь` обязателен для широкой совместимости.

## 10. ЗАПИСЬ В ЖУРНАЛ РЕГИСТРАЦИИ 1С

Все события записывать в стандартный журнал регистрации:

```
ЗаписьЖурналаРегистрации(
    "SmartRoute.Синхронизация",   // для успехов
    "SmartRoute.Ошибка",          // для ошибок
    УровеньЖурналаРегистрации.Информация / Ошибка,
    ,   // метаданные — не указывать
    ,   // объект — не указывать
    "Дата: ДД.ММ.ГГГГ | Результат: ..."
);
```

**Зачем:** IT-специалист клиента может диагностировать проблемы через стандартный журнал 1С без доступа к форме EPF.

## 12. ОШИБКИ И СООБЩЕНИЯ — ПОЛНЫЙ ГЛОССАРИЙ

| Код / Ситуация | Сообщение пользователю | Действие |
|---|---|---|
| Сеть недоступна | "❌ Нет связи с SmartRoute. Проверьте интернет. {ошибка}" | Повтор 3×5с |
| HTTP 401 | "❌ Неверный API-ключ. Сгенерируйте новый пакет." | Нет повтора |
| HTTP 403 | "❌ Ключ не имеет права orders:write." | Нет повтора |
| HTTP 422 | "❌ Ошибка в данных: {первые 500 символов ответа}" | Проверить реквизиты |
| HTTP 429 | "⚠️ Слишком много запросов. Подождите минуту." | Повтор через 60с |
| HTTP 5xx | "❌ Ошибка сервера SmartRoute. Попробуйте позже." | Повтор 3×5с |
| Ошибка SQL в 1С | "❌ Ошибка запроса. Неверные реквизиты: {список реквизитов}" | Исправить настройки |
| Нет заказов | "ℹ️ Нет проведённых заказов на {дата}." | Норма |
| Успех | "✅ Загружено {N} заявок. Совпало точек: {M}." | — |
| Новые точки | Добавить: "🆕 Создано {K} новых точек (нужно геокодирование)" | — |

## 13. СБОРКА EPF (для 1С-разработчика)

1. Открыть Конфигуратор 1С 8.3.15+
2. Файл → Новый → Внешняя обработка → Имя: SmartRoute
3. Добавить реквизиты объекта (раздел 2)
4. Формы → Добавить → Произвольная форма
5. Разместить элементы (раздел 3-4)
6. Вкладка «Модуль» → вставить содержимое `SmartRouteModule.bsl`
7. В `ПриСозданиеНаСервере`: URLSmartRoute = "{{BASE_URL}}", APIКлюч = "{{API_KEY}}"
8. Синтаксис → Проверить (ожидается 0 ошибок)
9. Файл → Сохранить как → Внешняя обработка (*.epf)
10. Обновить `version.json`: status="released", version="1.0.0", build_date=сегодня
